# 三麻 ノーマル華4 オンライン対戦

友達とルーム番号で集まって遊べる三人麻雀です（ノーマル華4ルール）。
空いた席はCPUが入るので、1人や2人でも遊べます。

## ファイル

- `server.js` … サーバー（ルーム・席・通信）
- `game.js` … 対局のルール処理（点数・祝儀・華牌など）
- `public/index.html` … 画面
- `package.json` … 必要なライブラリ（express / socket.io）
- `records.js` … 成績を GitHub の data ブランチに保存する
- `public/stats.html` … 成績表ページ（/stats）
- `gas/Code.gs` … 通算成績をスプレッドシートに記録する Apps Script（任意・旧方式）

## Renderで公開する手順（4人麻雀と同じ流れ）

1. GitHubで新しいリポジトリを作り、このフォルダの中身をそのままアップロード
2. Renderで「New +」→「Web Service」→ そのリポジトリを選ぶ
3. 設定
   - Runtime：Node
   - Build Command：`npm install`
   - Start Command：`npm start`
   - Instance Type：Free
4. 「Create Web Service」で公開。数分で `https://〇〇.onrender.com` のURLができます

## ルールの選択（ルーム画面）

ルームを作った人が、対局を始める前に選びます（対局中は変わりません）。

| 項目 | 選択 |
|---|---|
| 華 | 4枚／8枚／セブンスター |
| シュバ | あり／なし |
| 割れ目 | あり／なし |

### セブンスター
- 華牌4枚（春夏秋冬1枚ずつ）に加えて、7p・7sが6枚ずつ（黒3・虹1・華2）。全部で116枚
- 華の7：7pは春（ピンク）・冬（青）、7sは夏（緑）・秋（オレンジ）。牌の右上に印
- 虹の7：和了で祝儀3枚、ドラ1つ（秋で2倍）
- ドラ表示・裏ドラ表示に華の7が出たら、普通の7として8がドラになり、和了時にその華の効果も付く
- アリス・チューリップで華の7をめくったら、普通の7としての当たり＋華牌としての当たり（華牌の枚数）
- 手牌で華の7・虹の7（6枚）のうち4枚以上を使って和了したらサイコロ1回
- 7p・7sはそれぞれ6枚あり、5枚以上持つことも、5枚以上のときに暗槓することもできる（暗槓には普通の7→虹→華の7の順に4枚使い、華の7は手に残す）。ただし1人が和了に使えるのは7p・7sそれぞれ鳴きも含めて4枚まで（45677777 のような和了や、5枚目の7での待ちはできない）
- 7待ちでテンパイしている人は、相手が抜いた華の7でロンできる。その牌の華の効果も付き、春夏秋冬がそろえばサイコロ。見逃したらフリテン
- 特別な7は、手の中で普通の7として使っても、自分の番に抜いてもよい（華の7を上にスライドで抜く。切るときは3回タップ（間違えて切らないため））。抜いたら補充の牌を引く。リーチ後は、引いたその牌だけ「〇の7を抜く」ボタンか上にスライドで抜ける
- 抜いた特別な7は華牌1枚として数える（春の祝儀、アリス、春夏秋冬のサイコロなど）
- 手に持ったまま和了しても、その華の効果がある（表示牌の華牌と同じく和了時に付く）
- CPU は、切ろうとした牌が特別な7なら切らずに抜く

### 華8
- 華牌が春夏秋冬2枚ずつ（8枚）。補充牌も8枚
- 夏：1枚につきワンランクアップ（夏2枚で2ランクアップ）
- 秋2枚：赤5・金5は秋1枚と同じ2倍に加えて、普通の5は1枚でドラ1つ、抜き北は1枚でドラ2つ（北4枚なら 4＋秋秋4＋4枚そろい4＝12）
- 夏・秋・冬の枚数は、ドラ表示・裏ドラ表示（カンドラも）の華牌も数える（和了時に効く）
- 1枚目の春：抜いた時点で華牌の枚数×1枚。和了したら、ドラ表示・裏ドラ表示の華牌の枚数×1枚を追加（華4も同じ）
- 2枚目の春を抜いた時点では、1枚目の春の効果で1枚だけもらう
- 2枚目の春（自分で抜いた2枚目、または表示牌の春）：和了したときに、自分の華牌＋表示牌の華牌の全部の枚数×1枚（流局・放銃ではなし）
  - 例：春秋冬を抜いていて、裏ドラが春・夏 → 1枚目の春で2枚＋2枚目の春で5枚（春春夏秋冬）＝7枚ずつ
- 春夏秋冬が1そろいごとにサイコロ1回（8枚なら2回）。自分で抜いた華牌だけで数える（表示牌は数えない。華4も同じ）
- 冬2枚（表示牌の冬も数える）：アリスの代わりにチューリップ。めくり方・止まり方はアリスと同じ（山の最後から、当たらなくなるまで。上限なし）。めくった牌と前後1つ（9の次は1、白發中、東南西北はつながる）が手にあれば当たり。当たった手の牌1枚につき2枚（鳴いていたら1枚）。抜き北も持っている北として数える
- アリス・チューリップで華牌をめくったら、抜いた華牌＋ドラ表示・裏ドラ表示の華牌の枚数（門前なら2倍）。華4のアリスも同じ

### シュバ（シュバリー＝祝儀倍リーチ）
- リーチの牌を選ぶときに「シュバ棒も出す」を押すと、リーチ棒に加えてシュバ棒（100点棒）を出す。オープンリーチでも出せる
- シュバ棒は1人1本なので、1半荘に1回だけ。点数には関係しない（出しても持ち点は減らない）。次の半荘でまた使える
- シュバリーしたあとに本人がもらう祝儀はすべて2倍（和了の祝儀・サイコロ分・アリス・トビ賞・春の抜いた時点の分など）
- 2倍にならないもの：ウマ、8万点超えボーナス。シュバリー前にもらった分はさかのぼらない。放銃したときの支払いは普通通り
- CPU（空いた席・代打）はシュバリーしない
- リーチ（シュバリー）の宣言牌でロンされたら不成立：リーチ棒は払わない扱いで戻り、シュバ棒も使っていない扱い（その半荘でまたシュバリーできる）。普通のリーチ・オープンリーチも同じ

### 割れ目
- 局の始めに、アプリがランダムで1人を割れ目に決める（卓の点数の横に「割」の印）
- 割れ目の人が払う・もらう和了の点数と祝儀は2倍
  - 割れ目の人がツモ：2人とも2倍払う／割れ目でない人がツモ：割れ目の人の支払いだけ2倍
  - 割れ目の人のロン・割れ目の人の放銃：その支払いが2倍
- 2倍になるもの：和了の点数、和了時の祝儀、サイコロ分、アリス、包、流し役満、トビ賞、春の抜いた時点の分
- 2倍にならないもの：ノーテン罰符、本場、ウマ、8万点超えボーナス
- シュバリーと重なると4倍

例（子の満貫ツモ、普通は子3000・親5000）：割れ目の人がツモ→子6000・親10000／割れ目でない人がツモで割れ目が子→割れ目の子6000・親5000

## 遊び方

1. URLを開いて名前を入れ「ルームを作る」
2. 友達にルーム番号（4桁）を伝える。友達は番号を入れて「参加」
3. 全員が「準備OK」を押したら、ルームを作った人が「開始」（足りない席はCPU。3人とも人間なら全員OKで自動開始）
4. 終局したら、誰でも「部屋に戻る」でメンバー画面に戻れます。次の対局も全員の準備OKから

## 注意

- LINEでリンクを開くと、自動でSafariなど外のブラウザで開き直します（LINEの中のブラウザでは音声が出ないため）
- 音声は、最初に画面のどこかをタップしたあとから鳴ります

- Renderの無料プランは、しばらく誰も使わないと眠ります。最初に開いたときは起動に1分ほどかかります
- オーラス（親が流れたら終わる局）で親が和了したときは、親が「やめる（終局）」か「続ける」かを選べます。流局は必ず続行です。親がCPU・代打のときは、トップならやめます
- 自分の番で2分操作がないと、自動でツモ切りしてCPUが代わりに打ちます。「復帰する」を押すか開き直せば本人に戻ります
- 対局中にページを閉じても、同じ端末で開き直せば同じ席に戻れます。戻るまでの間はCPUが代わりに打ちます
- 対局の途中経過はサーバーのメモリにあるので、Renderが再起動するとルームは消えます

## 成績表（みんなで見られる管理表）

半荘が終わるたびに、結果が GitHub リポジトリの `data` ブランチ（`records/YYYY-MM.json`）に自動で保存され、
`https://（このアプリのURL）/stats` の成績表ページで週ごと（日曜はじまり）の通算と半荘ごとの記録が見られます。「Excel保存」で .xlsx もダウンロードできます。
表の形は `public/stats.html` で作っているので、ルールが変わってもこのファイルを直すだけで過去の記録ごと表示が変わります。

設定（最初の1回だけ）
1. GitHub の「Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token」
   - Repository access：Only select repositories → このリポジトリ
   - Permissions → Repository permissions → Contents：Read and write
2. できたトークン（`github_pat_…`）を Render の環境変数 `GITHUB_TOKEN` に入れて保存
3. 別のリポジトリに保存するときは `GITHUB_REPO`（例：`owner/repo`）も入れる

- 場代：1半荘ごとにトップから祝儀1枚×倍率を引き、「あつや」に足します（成績表の通算の集計に含まれます）。枚数と受け取る人は Render の環境変数 `FEE_CHIPS`・`FEE_TO` で変えられます。記録した時点の値で残るので、変えても過去の記録には影響しません
- 記録の修正は `data` ブランチの `records/YYYY-MM.json` を直接直せば、1分以内に成績表に反映されます
- `data` ブランチへの書き込みでは Render は再デプロイされません
- トークンの期限が切れると保存が止まります（Render のログに `records failed` と出ます）。作り直して入れ替えてください

## 通算成績をスプレッドシートに記録する（任意）

設定すると、半荘が終わるたびに結果が Google スプレッドシートに自動で書き込まれます。
週（日曜はじまり・日本時間）ごとに1枚のシートが自動で作られ、左に半荘ごとの記録、右にその週の名前ごとの通算（半荘数・着順・祝儀・祝儀×倍率）が出ます。
Render が眠ったり再起動したりしても記録は消えません。
ゲームの終局画面とルーム画面には、そのルームで終わった半荘の通算が出ます（全員がルームを出るとリセット）。

1. Google スプレッドシートを新しく作る（名前は何でもOK）
2. メニューの「拡張機能」→「Apps Script」を開き、最初からある中身を全部消して `gas/Code.gs` の中身を貼り付ける
3. 6行目の `"ここに合言葉を入れる"` を、自分で決めた合言葉（英数字で長めに。例：`sanma-7f3k9q2x`）に書き換えて保存
4. 右上の「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - 「デプロイ」を押し、Google アカウントのアクセス許可を「許可」する（「安全ではないページ」と出たら「詳細」→「（安全ではないページ）に移動」）
   - 表示された「ウェブアプリ」の URL（`https://script.google.com/macros/s/…/exec`）をコピー
5. Render のサービスの「Environment」で環境変数を2つ追加して保存（自動で再デプロイされます）
   - `SHEET_URL`：4 でコピーした URL
   - `SHEET_SECRET`：3 で決めた合言葉
6. スプレッドシート右上の「共有」で、みんなに「閲覧者」として共有する（リンクを LINE に貼っておくと便利）

- 週のシートの名前は「2026/10/4〜10/10」のようになり、新しい週ほど左に並びます
- ルーム画面の「倍率」（ルームを作った人が入力。はじめは100）が、記録の「倍率」「祝儀×倍率」の列に入ります。倍率は対局を始めたときの値で記録します
- 名前で合計するので、毎回同じ名前で入ってください
- 最初からCPUが入っている半荘は記録しません。人3人で始めた半荘は、途中で切断してCPUが代打になっても本人の名前で記録します
- 記録の行を消したり直したりしたら、そのシートを開いてメニュー「三麻」→「この週の通算を再計算」で通算に反映されます
- `gas/Code.gs` を書き換えたときは、「デプロイ」→「デプロイを管理」→ 鉛筆マーク → バージョン「新バージョン」で更新します（URL は変わりません）

## テスト

```
npm install
npm test
```

- `test/selfplay.js`：CPUだけで何半荘も続けて打たせて、止まる・エラー・点数や祝儀のずれ・同じ結果の出し直しがないかを確かめます
- `test/deal-check.js`：山を何万回もシャッフルして、配牌に偏りがないかをカイ二乗検定で確かめます

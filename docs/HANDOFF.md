# 引き継ぎメモ（GOTO：三麻 ノーマル華4 オンライン）

新しいチャット・新しいアプリで「卓・キャラクター・演出を同じ仕様にする」ためのメモです。
細かいルールは `README.md` と `public/rules.html`（アプリ内の説明書）が正です。このメモは「どこに何があるか」と「決まっていること」をまとめたものです。

---

## 1. 全体の作り

| ファイル | 中身 |
|---|---|
| `game.js` | 対局エンジン（サーバー・ブラウザ共通）。牌・和了判定・点数・祝儀・CPU・局の進行。`createGame(hooks)` で1対局を作る |
| `server.js` | Node.js（express + socket.io）。ルーム・席・再接続・手番タイマー・各人への画面データ（`viewFor`）・成績保存の呼び出し・アイコン |
| `records.js` | 成績を GitHub のブランチに JSON で保存（`records/YYYY-MM.json`） |
| `public/index.html` | 画面のすべて（HTML・CSS・JS が1ファイル）。卓・手牌・結果画面・ロビー・キャラクター・演出・音 |
| `public/rules.html` | 説明書（`/rules`） |
| `public/stats.html` | 成績表（`/stats`）。Excel 保存あり |
| `public/icons/` | ホーム画面アイコン（`main-*.png`＝本番の緑、`test-*.png`＝テスト版の青に「テスト」の帯） |
| `test/selfplay.js` | CPU だけで半荘を回して落ちないか確かめる（`node test/selfplay.js 30`） |
| `render.yaml` | Render の設定例（Build は `npm install`、Start は `node server.js`） |

ルート直下の `client.js` `effects.js` `tiles.js` `style.css` `index.html` などは、昔の別アプリ（四人麻雀）の残りで、**今は使っていません**（サーバーが配るのは `public/` だけ）。

### 画面データの流れ
- サーバーが正。ブラウザは `view`（対局中）・`result`（和了・流局）・`final`（終局）・`lobby`（部屋）を受け取って描くだけ。
- **席は人ごとに回して送る**（`rotArr` / `rotR`）。どのブラウザでも「自分＝席0（下）、席1＝右（下家）、席2＝左（上家）」。
- 操作は `socket.emit("act", {...})`、次へは `next`、和了やめは `yame`。

### 牌の番号（`k`）
- 0〜8：萬子（三麻なので 1萬=0 と 9萬=8 だけ使う）
- 9〜17：筒子、18〜26：索子
- 27〜30：東南西北、31〜33：白發中
- 34〜37：華牌（春夏秋冬）
- 牌の印：`red`（赤5）、`gold`（金5）、`rainbow`（虹の7）、`fk`（華の7＝特別な7。値は 34〜37 のどの華か）、`pocchi`（白ポッチ）

## 2. 卓の画面（`public/index.html`）

### 大きさの決め方（CSS 変数）
- `--bw`（卓の横幅）、`--bh`（卓の高さ。縦画面・横長画面で使う）、`--rt`（卓の上の牌1枚の幅）、`--hw`（手牌1枚の幅）、`--handH`（手牌の帯の高さ）、`--box`（真ん中の箱の大きさ）
- 画面の向きで3パターン：
  - **縦画面**（`@media (orientation: portrait)`）：卓を縦長にして上下の空きを使う
  - **スマホ横画面・PC・iPad**（`(orientation: landscape) and (max-height: 560px), (orientation: landscape) and (min-aspect-ratio: 13/10)`）：卓を横長にして画面いっぱい。左にボタン列、右に操作ボタン
  - それ以外（正方形に近い画面）：正方形の卓

### 卓の部品
- `seatLayer(s)`：1人分の層（`.layer.me` / `.layer.r` / `.layer.l`）。層ごと回転（右 -90°、左 90°）させて同じ HTML で3方向を描く
  - `.rvg` 河（6枚で折り返し。**縦画面の左右の人だけ、13枚目からは3段目を横に伸ばす**＝4段目を作らない）
  - `.edge` 手牌の裏（相手）・鳴き・抜き牌
  - `.nm` 相手の名前、`.av` キャラクター、`.stick` リーチ棒、`.wmband` 割れ目の帯（赤い斜線）
- `.box` 真ん中の箱（局・本場・供託・残り枚数）。`.sc` は各人の点数行（風・点数・祝儀）。**長いときは `fitSc()` で行ごと縮める**（角で重ならないよう、箱の内側 58% に収める）
- 親：風の字を赤（`.wd.oya`）、キャラに赤い丸の「親」（`.oyatag`）
- 待ちの表示 `waitBarHTML()`（縦画面は手牌の上、横長画面は卓の左外）
- `render()` で卓全体を描き直す（`H` と `V` から作る）

### 手牌の操作
- タップで選んで、もう一度タップで切る
- 華の7：**長押しで抜く**（`LP_MS` 450ms、iPhone は touch イベント）、**3回タップで切る**
- 北・華牌は「北」「華」ボタン。ポンの直後は北・華牌・華の7とも抜けない（1枚切るだけ）

### 結果画面
- `showResult(page)`：和了（ダブロンはページ分け）・流局。ドラ表示・裏ドラ表示・アリス／チューリップのめくり、手牌、役、精算表
- `fitResult()` / `refitResultSoon()`：iPhone で下が切れないよう縮めて収める（中はスクロールもできる）
- 金枠（和了の祝儀10枚以上）・虹枠（20枚以上）
- `showFinal(order)`：終局（順位・ウマ・通算・全局の精算＝順位の並び）

## 3. キャラクター（`public/index.html`）

- `CHARS`：8種類、すべてオリジナルの SVG（友達麻雀のキャラは使えないので自作）
  - ミケ（ネコ）、ポチ（イヌ）、モモ（ウサギ）、ゴン（クマ）、コン（キツネ）、リンリン（パンダ）、ペン太（ペンギン）、ケロ（カエル）
  - それぞれ `name`（名前）、`kind`、`col`（色）、`line`（リーチのひとこと）、`svg`（100×100 の中身）
  - 目・頬・口は共通の部品（`EYES` `CHEEK` `MOUTH`）
- `avSVG(番号)`：丸い背景つきの SVG を返す
- 選び方：トップ画面と部屋の画面（`avPickHTML()`）。端末に保存（`localStorage` の `sanma-online` の `av`）。サーバーへは `create` / `join` / `setAvatar` で送る
- サーバー：`p.av` を席に持ち、開始時に `room.avatars` を作る（CPU は人間とかぶらないものを自動）。`viewFor` の `avatars` で回して送る
- 卓の表示：各席の角に `.av`。**リーチ中は赤く光る枠＋赤い「リーチ」札**（オープンはオレンジの「オープン」）
- **リーチのカットイン** `riichiCutIn(席, 文字)`：キャラの色の帯が横切り、キャラが飛び込んで大きく「リーチ」＋ひとこと。1.9秒。音声の `se`（`リーチ`・`オープンリーチ`・`シュバリー`・`シュバオープン`）に合わせて出す

## 4. 演出・音（`public/index.html`）

- **雷** `thunder(lv)`：和了した人がもらった祝儀の合計で4段階（30／50／100／150枚以上＝雷・大雷・超雷・神雷）。**ツモ・ロンを押した瞬間（結果画面が開いたとき）**に鳴る。稲妻（SVG）・光・カードの揺れ・音（`SE.thunder`）・振動
- **アリス・チューリップ**：結果画面で山の最後からめくる。当たった牌は手牌で光る（`sparkle`。華牌の当たりは手牌の華の7も光る）。結果は和了した人ごと（`w.alice`）
- **サイコロ** `DICE`：役満などで2人から。ゾロ目は光る、ピンゾロは20として数えて振り直し
- 音 `SE`：Web Audio で作った音（打牌・ツモ・雷など）＋ブラウザの読み上げ（ロン・ツモ・リーチなど）。音のオン・オフは保存

## 5. ルール（要点。詳しくは `public/rules.html` / `README.md`）

- 三麻・35000点持ち・精算は祝儀チップ。華は 4枚／8枚／セブンスター（華の7）をルームで選ぶ。シュバ（祝儀倍リーチ）・割れ目もルームで選ぶ
- 祝儀：赤5 1枚、金5 2枚、虹の7 3枚、抜き北 1枚、裏ドラ、一発、役満・数え役満、サイコロ、春・アリスなど（`winChips`）
- 倍率：シュバリーした人がもらう祝儀は2倍、割れ目の人が払う／もらう祝儀は2倍（`chipMult`）
- 秋：赤5・金5・虹の7が2倍。秋秋：華牌の数（抜いた華牌・華の7、手牌の華の7、ドラ表示・裏ドラ表示の華牌）がドラ
- 春：1枚目は表示牌の華牌の数、2枚目は全部の華牌の数（名前は出どころに合わせて「手牌の春」「表示牌の春」など）
- 自動和了：和了できるとき 20秒で自動ツモ・ロン（キャンセル可）
- 3人目の追っかけリーチ（ほかの2人がリーチ中）はオープンリーチできない
- 萬子混一色は役満、三風・三連刻は2翻、四連刻は役満、七対子はロン30符・ツモ25符

## 6. サーバーと運用

### 2つの Render サービス（同じリポジトリ）
| 呼び方 | URL | ブランチ | 環境変数 | 中身 |
|---|---|---|---|---|
| テスト版 | https://goto-v7z3.onrender.com | `test` | （`FRIENDS_ONLY` なし） | CPU 対戦あり。成績は記録しない。チャット（コメント）機能あり |
| 本番 | https://friends-only-goto.onrender.com | `main` | `FRIENDS_ONLY=1`、`GITHUB_TOKEN`、`NODE_VERSION=20` | 友達3人専用（CPU なし・3人そろって開始）。成績を記録 |

- 成績の保存先：本番は `data-friends` ブランチ、テスト版は `data` ブランチ（昔の記録）。`DATA_BRANCH` で上書きできる
- Render の Build Command は **`npm install`**（`echo no build` だと express が入らず起動に失敗する）
- 無料プランなので、しばらく使わないと眠る（最初の起動に 30秒〜1分）

### 再接続
- 端末に目印（`token`）を保存。同じブラウザで開き直せば同じ席に戻る
- 目印が消えても（LINE の中のブラウザを閉じた等）、**同じ名前で「参加」すれば戻れる**。ただし**その席の人がつながっている間は入れない**（乗っ取り防止）
- 落ちている間は CPU が代打ち。結果画面で全員いないときは進めない
- デプロイ後に古い画面のままつないだら自動で読み直す（`BUILD` の印を比べる）

## 7. 進め方の決まり（このユーザーとの約束）

- 返事は日本語・わかりやすく。ユーザーは主に iPhone（LINE の中のブラウザや Safari）で見ている
- 直したものは**まずテスト版（`test` ブランチ）に入れる**。ユーザーが「push」と言ったら本番（`main`）に入れる
- 本番を更新すると、そのとき打っている対局は消える（対局が終わってから入れる）
- 画面を変えたら、iPhone 縦・iPhone 横・PC でスクショを撮って確かめる（Playwright。`NODE_PATH=$(npm root -g)`）
- ルールの変更は `game.js`・説明書（`public/rules.html`）・`README.md` をそろえて直す
- 記録の削除などデータを消す作業は、必ずユーザーに確かめてから
